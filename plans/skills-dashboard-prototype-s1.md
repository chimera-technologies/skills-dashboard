# Plan: S1 App scaffold, toolchain and test harness

## Story
Create the Vite + React + TypeScript project with Vitest (+ Testing Library),
Playwright (Chromium, Firefox, WebKit) and axe-core, building to static files
in `dist/`, so every later story has working `npm test`, `npm run test:e2e`
and `npm run test:file -- {file}` commands. Foundation for REQ-10, REQ-12
and REQ-13 (no external hosts); no screen of its own (design.md "No UI": S1).

## Edge cases
- Clean checkout with no `node_modules/` or `dist/`: `npm ci` uses the committed lock file; the Playwright `webServer` always runs `npm run build` before `preview` and never reuses a running server (`reuseExistingServer: false`), so E2E never tests a stale or missing `dist/` (AC-1, AC-2, EC-5 tests).
- Lock file out of sync with `package.json`: `npm ci` would fail on a clean checkout; caught offline by the lock-sync check in "S1 AC-1: ...".
- Vitest picking up Playwright specs (they import `@playwright/test` and would crash under jsdom): Vitest `include` is limited to `tests/unit/`; Playwright `testDir` is `tests/e2e/`. Covered by the full `npm test && npm run test:e2e` run in Step 5.
- `test:file` with no argument, two arguments, a missing file, a directory, a file outside `tests/unit/`/`tests/e2e/`, or `..` escaping: usage error exit 2 (tests/unit/toolchain.test.ts › "S1 EC-3: ..."). Equivalent spellings (`./`, absolute, `\`) route the same as the canonical path ("S1 EC-1: ..."). Dispatch is checked with `TEST_FILE_DRY_RUN=1`, which prints the command and env instead of running it.
- Runner missing or killed: non-zero exit, never a silent pass ("S1 EC-4: ...").
- Static build opened from a sub-folder: `base: './'` gives relative asset URLs; asserted in "S1 AC-2: ...".
- Requests to other hosts (fonts, CDNs, analytics, WebSockets, workers, late timers) slipping in later: `guardOrigin` blocks and records any non-origin URL for the whole test and keeps recording 2 s after `networkidle`, in all three engines; it stays in the suite as the REQ-13/SEC-7.1 guard for later stories ("S1 AC-3: ...", "S1 BUG-1: ..."). Browser favicon requests go to the same origin and pass.
- Port 4317 already in use: with `reuseExistingServer: false` and `--strictPort`, Playwright fails fast with a "port already used" error instead of testing whatever answers there. A manual `npm run preview` uses Vite's default 4173 and does not clash.
- Registry unreachable: unit test files never call npm (EC-6), so `npm run test:file` works offline; `npm test` then fails in `audit-check.mjs` with npm's error message, not a TypeError (EC-2).
- Three browser projects in parallel against one preview server: read-only static files, safe to share.
- 1024 px minimum width (REQ-12): all E2E projects run at 1024x768.
- Accessibility harness: tests/e2e/scaffold.spec.ts › "S1 harness: axe-core finds no violations on the shell" proves `@axe-core/playwright` is wired up (header/main landmarks, `lang`, title present).
- Node version other than 22: `engines` plus `.nvmrc` document it; CI uses `node@22` from `toolchains`.
- State from earlier stories: none; the repo has no `package.json`, `src/` or `tests/` yet. Existing `.gitignore` entries are kept and only appended to.

## Steps
1. Create `package.json`, `.nvmrc`, configs (`vite.config.ts`, `playwright.config.ts`, `tsconfig.json`), `scripts/test-file.mjs`, `scripts/audit-check.mjs`, and extend `.gitignore`.
2. `npm install` the pinned dependencies to produce `package-lock.json`; `npx playwright install --with-deps` for the three engines.
3. Write the failing tests and fixtures: tests/unit/toolchain.test.ts (AC-1, AC-4, EC-1 to EC-4, EC-6), tests/unit/fixtures/audit/, tests/unit/App.test.tsx, tests/e2e/helpers/origin-guard.ts, tests/e2e/scaffold.spec.ts (AC-2, AC-3, EC-5, BUG-1, axe). Run each with `npm run test:file -- <file>` and confirm they fail because the app files are missing.
4. Add `index.html`, `src/main.tsx`, `src/App.tsx`, `src/index.css`; re-run each test file until green.
5. Run `npm ci && npm test && npm run build && npm run test:e2e` once from a clean state (`rm -rf node_modules dist`), then `validate_plan.py --check-tests` and the preflight (builds the graph for the first time).
6. Verifier, then build report.

## Risks and rollback
- New project, no runtime behaviour beyond a placeholder page; rollback is reverting the PR.
- `npm audit` results change over time as advisories are published; a later advisory can turn AC-4 red without a code change. That is intended (SEC-5.1), but the fix is a dependency bump in whichever story is open.
- Decision to confirm: AC-4's live `npm audit` runs at the end of the `npm test` script (so `test_command` needs the npm registry), while the AC-4 unit test checks the audit verdict logic against fixtures offline.
- `test:file` uses `npx` without a shell, which Windows needs as `npx.cmd`; CI and the build runners are Linux. On Windows the spawn error now exits 1 (EC-4) instead of passing.
- Decision to confirm: `jsdom` is added as the Vitest DOM environment for Testing Library; the spec names Testing Library but not the DOM environment.
- Decision to confirm: Node is pinned to major 22 (`.nvmrc` and `engines`), matching `.sdlc/build.yaml`, rather than an exact patch version.
- Decision to confirm: AC-1 "succeed on a clean checkout" is proven by CI running `install_command` and `test_command` on a fresh runner plus the AC-1 test's lock-file and script checks; a test cannot run `npm ci` on its own checkout without deleting its own `node_modules`.

## Out of scope
- Any screen, routing, data loading, CSV parsing or metrics (S2 to S8).
- Design tokens beyond the few base styles the placeholder page needs (S4 builds the shared header and layout).
- Performance budgets (S8) and the full keyboard walk-through (S8).
- CI workflow or `.sdlc/build.yaml` changes; linting and formatting tools.
